# DEFENSA TÉCNICA DEL SISTEMA DE EXPANSIÓN DE CONSULTAS, RETROALIMENTACIÓN Y FILTRADO DE DOCUMENTOS

## 1. Decisión: Expansión de consultas siempre activa

**Qué se defiende:**
Se decidió implementar un esquema de expansión de consultas siempre activo dentro del pipeline de recuperación de información.

**Justificación:**
El sistema aplica un enfoque de *Pseudo-Relevance Feedback (PRF)* en dos etapas:

1. Recuperación inicial de documentos.
2. Expansión de la consulta basada en dichos documentos.
3. Recuperación final optimizada.

Este enfoque permite mejorar el recall sin afectar la experiencia del usuario, ya que los resultados intermedios no son visibles.

**Valor técnico:**

* Mejora la cobertura semántica de la consulta.
* Reduce dependencia de la formulación exacta del usuario.
* Mantiene una interfaz limpia (similar a sistemas tipo ChatGPT).

---

## 2. Decisión: Separación de feedback explícito e implícito

**Qué se defiende:**
Se implementaron dos endpoints diferenciados:

* `/feedback` (explícito)
* `/feedback/implicit` (implícito)

**Justificación:**
Las señales explícitas representan juicios conscientes del usuario, mientras que las implícitas reflejan comportamiento inferido.

**Valor técnico:**

* Evita sesgos en el modelo de retroalimentación.
* Permite asignar distintos pesos a cada tipo de señal.
* Mejora la interpretabilidad del sistema.

---

## 3. Decisión: Normalización de eventos de interacción

**Qué se defiende:**
Eventos como `copy_url` y `open_source` se agrupan en una única señal: `source_interaction`.

**Justificación:**
Ambos eventos representan la misma intención: interés en la fuente.

**Valor técnico:**

* Evita duplicación de señales.
* Reduce ruido en los datos de feedback.
* Mejora la calidad del aprendizaje del sistema.

---

## 4. Decisión: Uso del algoritmo de Rocchio

**Qué se defiende:**
El algoritmo de Rocchio se utiliza exclusivamente para expansión de consultas, no para ranking completo.

**Justificación:**
Rocchio permite ajustar la representación de la consulta en función de documentos relevantes y no relevantes:

q' = αq + βDr − γDnr

**Valor técnico:**

* Integra feedback explícito de forma formal.
* Mejora la selección de términos de expansión.
* Mantiene desacoplado el sistema de ranking principal.

---

## 5. Decisión: Persistencia en JSON

**Qué se defiende:**
El sistema utiliza archivos JSON para almacenar la retroalimentación.

**Justificación:**
Se prioriza simplicidad, trazabilidad y facilidad de inspección sobre escalabilidad.

**Valor técnico:**

* Facilita debugging y validación experimental.
* Permite reproducibilidad de resultados.
* Adecuado para contexto académico.

---

## 6. Decisión: Expansión híbrida de consultas

**Qué se defiende:**
Se combinan múltiples técnicas:

* Sinónimos
* Co-ocurrencia
* Pseudo-relevance feedback
* Feedback explícito e implícito
* Rocchio

**Justificación:**
Ninguna técnica individual es suficiente para capturar toda la semántica de una consulta.

**Valor técnico:**

* Aumenta robustez del sistema.
* Mejora recall y precisión simultáneamente.
* Alineado con sistemas modernos de recuperación híbrida.

---

## 7. Decisión: Filtrado multi-etapa en el crawler

**Qué se defiende:**
Se implementa un pipeline de filtrado en capas para evitar documentos irrelevantes.

**Estructura:**

1. Filtro estructural (tipo de contenido, tamaño, formato)
2. Filtro léxico (coincidencia con query)
3. Filtro semántico (TF-IDF o embeddings)

**Justificación:**
El problema principal no es de ranking, sino de calidad de datos de entrada.

**Valor técnico:**

* Reduce ruido en el índice.
* Mejora eficiencia del sistema.
* Evita procesar contenido irrelevante (audio, video, spam).

---

## 8. Decisión: No usar LSI como filtro principal

**Qué se defiende:**
LSI no se utiliza como mecanismo principal de filtrado de documentos.

**Justificación:**
LSI está diseñado para modelar relaciones latentes, no para filtrar calidad de contenido.

**Valor técnico:**

* Se evita sobrecarga computacional innecesaria.
* Se utilizan métodos más adecuados (embeddings, TF-IDF).
* LSI se reserva para análisis experimental o comparación.

---

## 9. Decisión: Uso de embeddings o TF-IDF para filtrado semántico

**Qué se defiende:**
Se emplean medidas de similitud semántica para validar relevancia de documentos.

**Justificación:**
Permite detectar similitud conceptual más allá de coincidencias léxicas.

**Valor técnico:**

* Mejora precisión del filtrado.
* Reduce falsos positivos del crawler.
* Compatible con arquitectura RAG.

---

## 10. Decisión: Arquitectura modular

**Qué se defiende:**
El sistema está dividido en módulos independientes:

* QueryExpander
* FeedbackStore
* Retriever
* RAG pipeline

**Justificación:**
Permite mantenimiento, escalabilidad y experimentación.

**Valor técnico:**

* Facilita pruebas A/B.
* Permite reemplazo de componentes sin afectar el sistema completo.
* Alineado con buenas prácticas de ingeniería.

---

## 11. Decisión: Aprendizaje progresivo del sistema

**Qué se defiende:**
El sistema mejora sus resultados en función del feedback acumulado.

**Justificación:**
Se implementa un enfoque iterativo donde el sistema aprende del usuario.

**Valor técnico:**

* Mejora resultados en consultas futuras.
* Introduce comportamiento adaptativo.
* Alineado con sistemas modernos de búsqueda inteligente.

---

## 12. Evaluación del sistema

**Qué se defiende:**
Se utilizan métricas clásicas de recuperación de información:

* Precision@k
* Recall@k

**Justificación:**
Permiten comparar el rendimiento con y sin expansión.

**Valor técnico:**

* Validación cuantitativa del sistema.
* Base para análisis experimental.
* Posibilidad de extensión a métricas más avanzadas.

---

## CONCLUSIÓN GENERAL

El sistema propuesto integra técnicas clásicas de recuperación de información con enfoques modernos de expansión de consultas y retroalimentación, dentro de una arquitectura modular y extensible.

Las decisiones tomadas priorizan:

* Calidad de resultados
* Interpretabilidad
* Modularidad
* Validez experimental

Esto permite que el sistema sea no solo funcional, sino también defendible desde un punto de vista académico y técnico.
